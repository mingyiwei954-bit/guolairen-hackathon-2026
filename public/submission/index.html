2026 年 9 月 15 日迭代版 · 灵魂匹配局：社区连接与兴趣社交

同一个问题，听见不同人生阶段的声音。

一、为什么做
一个大学生问“我最近不太快乐，怎么办？”，孩子可能说“吃个雪糕吧”，工作多年的人可能说“先出去走走”。我们想让这些原本不容易相遇的视角，在同一个问题下相遇。求学、工作、退休是首版浏览维度，不是经验高低的评价。产品服务于愿意分享生活经验、理解另一阶段的人，让讨论从寻找标准答案转向理解彼此。

二、这一版可以怎样体验
进入首页“过来人”，选择“听过来人说／听没过来人说”和人生阶段，看到对应人群的回答。问答上下错位，人生阶段与内容相伴；最热内容优先，其余内容可刷新轮换。
点开问题后连续上下阅读，同题不同经历之间用轻符号分隔。公开昵称与头像帮助建立联系，可以点赞、点亮黄色收藏星，也可以展开沿竖线排列的追评继续讨论。返回时保留浏览位置，页面采用轻缓的左右推入、拉出过渡。
“写回答”打开完整编辑器：文字、最多 4 张图片、3 个话题、5 个标签，支持草稿和图片放大。用户确认发布后保存到本项目数据库。话题检索调用知乎官方内容搜索，展示相关知乎内容与原链接；平台未提供的话题 ID 和站内发布能力不会伪造。
点击“问问看山”，看山居中思考，页面轻缓移动一次到思考区域。答案以文字淡入呈现，内容出现后保持阅读位置。用户可以查看来源、手动刷新；另保留基于资料的有限三问与追问转真人提问链路。

三、AI 与知乎的连接
看山回答由独立 Answer Agent 组织：本地资料检索、官方联网搜索、DeepSeek 生成、引用约束和程序校验。来源 URL 由程序给定，模型不能编造。搜索摘要与全文严格区分，资料不足、额度不足或模型失败有对应提示。
来源资料库收录知乎官方社区搜索摘要，以及活动开放的知识与故事素材；保留原始链接、内容范围和类型。故事标记为 fiction，排除在看山的事实证据检索之外。用户可在资料库查看来源，不把模型生成的内容再次作为事实来源。
本项目已经接入知乎 OAuth 登录。普通浏览与本项目内问答沿用访客会话；人生阶段来自用户自述，不能由外部作者文风推断。

四、让评委能体验完整社区链路
演示开关开启时，发布提问或回答后约 2 秒出现模拟赞同通知，随后出现两条简短 AI 角色回应。角色带有设定年龄、人生阶段和表达约束，结合检索资料生成 1–2 句话；失败时使用短模板。虚拟角色标识为 AI 角色，不代表真实知乎用户。该链路仅在演示站运行，不向知乎社区自动发帖。
信息流提供近百个问题的 mock 场景，含千赞、万赞的热度梯度；热门回答配有 34–40 条 mock 追评。昵称、初始点赞与这些追评是演示数据，不代表真实活跃、增长或用户规模。真实访客的新提交独立持久化，部署保留线上已有数据。

五、技术与可靠性
原生 JavaScript/CSS、Python HTTP 服务、SQLite、HTTPX、DeepSeek。手机使用自然视口，电脑以手机容器演示；图片在服务端验证并去除元数据后保存。模型请求通过并发控制、请求 ID 和持久化状态避免重复生成；后台网络等待不持有数据库写事务。
发布采用 Git 提交、版本包、数据库备份与增量迁移，代码版本可回退。密钥仅在服务端配置，不进入公开源码和前端。

六、验证与下一步
已实际检查连续阅读、导航过渡、问问看山的定位和稳定显示、图文编辑与图片查看、话题搜索、点赞收藏、追评展开、热门排序和模拟通知。后端覆盖媒体权限、评论幂等、角色约束、资料与引用、登录和问答回归。尚无真实规模负载、用户留存和全机型触摸测试，不把演示反馈等同于真实社区数据。
下一步邀请不同阶段的人围绕同题真实回答，观察是否看到新的角度、是否愿意继续讨论，再决定阶段维度和互动机制的扩展。
